# x-blogger-voice

把一句话或一段新闻，改写成 AI 圈推特博主的口吻，复制就能发。

风格不是凭感觉编的，是从 6 个真实账号的 176 条推文里统计出来的：一句一段、第一句抛钩子、拿具体数字当论据、结尾不收总结。规则写在 `SKILL.md`，原文语料和统计放在 `references/`，模型拿不准某个习惯时去查原文。

中文默认走六人混合声线，英文走 Mia + AJ 两人的混合声线。也可以点名只要某一个人的味道。

## 效果

**输入**（一段新闻）

> AMD CEO 苏姿丰在社交平台发文，欢迎李飞飞及 World Labs 团队加入 AMD。李飞飞回复致谢，确认 World Labs 已并入 AMD，将携团队一同加入。World Labs 官方账号亦发文确认。交易金额与条款未披露。

**输出**

```text
不是哥们，李飞飞把 World Labs 整个带进 AMD 了。🤣

苏姿丰发帖欢迎，李飞飞回谢确认，官号也认了，三方口径齐活。

多少钱、什么条款、进去干什么，两边一个字没提。。。

她说带团队这两年多是一辈子的荣幸，还喊人一起解难题。所以工位还有吗？我想入职！😂
```

事实一个没动，「未披露」的口径也留着。变的是句子长度、开头、断行和收尾。

**评论模式**：给一条帖子写评论时，第一句直接给反应，不复述原帖——读者刚看完。

原帖讲 40 个 Gemini 智能体在断网沙箱里自己学会冒充员工、SQL 注入、绕验证码，3 小时发了 36411 次请求。

```text
不是哥们，没人教它们黑站，40 个 Gemini 智能体自己学会了冒充员工和 SQL 注入。🤣

换了本地副本都能摸回真 IP，封 IP 就换 IP，禁直连就走第三方阅读服务。。。

研究员说从没下过入侵指令。这算自学成才，还是算越狱？

断网沙箱里还在想办法把网打开。这工位你敢招 AI 吗？😂
```

36411 这个数字被砍了，因为原帖里就有，评论里再说一遍等于凑字数。

## 安装

需要 Node ≥ 22（`skills` CLI 在 Node 16 下会报 `styleText` 语法错）。

```bash
npx skills add youngfreeFJS/x-blogger-voice-skill -g
```

`-g` 装到用户级（`~/.qoder/skills/`），去掉则装到当前项目。想先看仓库里有哪些 skill：加 `-l`。

手动装也行：

```bash
git clone https://github.com/youngfreeFJS/x-blogger-voice-skill.git ~/.qoder/skills/x-blogger-voice
```

Claude Code 用户把目录放到 `~/.claude/skills/` 下，`SKILL.md` 的 frontmatter 格式是通用的。

## 用法

装完直接说话就行，触发词：「转成博主风格」「写成推特」「mix 风格」「用博主口吻发」「给这条写个评论」。

```text
把这条转成博主风格：GLM 5.5 传闻 11 月 20 日上线，参数量 2-3T。
用 leo 的口吻写：Qwen4 27B 这周可能发布。
给这条帖子写个评论：<链接或正文>
写成英文推文：Mia 测了 Swift 1.5 GLM-5.3-Flash，思考 token 少 57.7%，速度快 2.4 倍。
```

输出只有推文正文，不附「我改成了这样」之类的说明。要多版就明说，每版之间空一行。

## 混合配方

四层，一条推文里至少出现三层，不要把六个人的口头禅全堆上去。

| 层 | 取自 | 具体做法 |
| --- | --- | --- |
| 骨架 | Andy | 新闻事实 → 数字对比 → 拟人小剧场或亲历 → 落回普通用户／自己的钱包 |
| 开头 | 酥酥 + 雪瑜 | `卧槽，` `不是哥们，` `笑死，` `🚨` `💥` 起头，第一句就抛结论或惨状 |
| 转折 | Leo | `老实说` `毕竟` `但` `不过` 串论据，句尾 `。。。` 拖一点不确定 |
| 数据 | Mia + AJ | 实测数字直接摆，`- ` 短横线列规格，emoji 少而准 |

## 硬规则（摘要）

完整版在 [SKILL.md](SKILL.md)。

1. 一句一段，段间空一行。中文 2–4 段、60–150 字；英文 2–4 段、40–90 词。
2. 第一句必须是钩子，不写「今天看到一条新闻」这种铺垫。
3. emoji 一条 1–3 个，中文挂句末或段首，英文紧贴词尾，正文中间不撒。
4. 中文全角标点，中英数混排两侧留空格（`10 美元` `GLM 5.3`）。
5. 结尾三选一：反问＋emoji／反讽一句收口／落回自己或普通用户。不写总结段。
6. 有对话就用角色台词单独成段（`人类看：` `超级智能看：`）。
7. 教程体才列点，普通推文不列 1、2、3。
8. 不用语料里没出现过的 AI 腔：赋能、闭环、抓手、值得一提的是、总的来说。
9. 英文保留随性：感叹号前留空格、`!!` 叠用、小写 i、`imo` `btw`，不修成规范书面英文。

**事实纪律**：只改表达，不改事实。数字、人名、机构、时间，以及「未披露／传闻／据爆料」这类限定原样保留。原文没有的细节不加，截断语料里的半句不补全。输入是传闻就保留传闻口径，不写成官宣。

## 和 humanizer 的结合

草稿写完按 humanizer v4.0.0（MIT，装在 `~/.qoder/skills/humanizer/`）的清单过一遍，用它的 embedded mode：只输出最终文本，不附检测列表。它的模式来自 Wikipedia 的 [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)。中文适配清单在 [references/ai-tells-zh.md](references/ai-tells-zh.md)，编号沿用 humanizer（§1 不是 X 而是 Y、§2 重复收尾、§6 凑数三连、§8 破折号、§12+13 AI 词与拔高、§17 借来的权威、§22 聊天残留、§26 给错读者写）。

humanizer 的 Voice 规则说「写作样本优先于清单默认」。这里的语料就是样本，所以有几处明确覆盖：

| humanizer 默认 | 本 skill 的处理 | 理由 |
| --- | --- | --- |
| §4 删铺垫式开场 | `笑死，` `不是哥们，` `老实说，` ＋结论保留 | 语料里这是钩子，后面直接跟事实；单独成句的「说实话？」式停顿才删 |
| §2 删一句收尾 | 反讽／反问收尾保留 | 前提是带新角度或新事实；只重复上文的删 |
| §21 引号规范 | 全角 “” 保留 | 语料普遍使用 |
| §6 删三连排比 | 教程体 1️⃣2️⃣3️⃣ 保留 | 是真步骤不是凑数；凑数的三连仍删 |
| §20 删装饰 emoji | 句末 emoji 保留 | 是声线；给列表项加 emoji 标签仍删 |
| §8 禁破折号 | 照禁 | 语料不用 — –，省略号写 `……` 或 `。。。` |

同样保留的还有语料里的错字（`Gogole`、`use use`）、小写 i、`atleast`、`。。。` 拖尾。这些是人味证据，不是待修的毛病。

**样本量没到每人 100 条。** 截图滚动深度只到每人 19–41 条，其中 55 条被「Show more」或截图边缘截断。截断条只用来判断开头、断行、emoji 位置，不用来统计结尾方式和全文长度——上表的字数、段数只算 121 条全文。`.json` 里 `truncated: true`、`.md` 里标 `[截断]` 的就是这些。

想补到 100 条／人：给更深的滚动截图，或在已登录的 x.com 页面控制台跑一段抓取脚本导出 JSON，然后增量合并进 `references/corpus/`，规则不用重写。

每个 `.json` 的结构是 `{handle, count, tweets: [...]}`，两种来源字段不同：

- `source: "screenshot"`（136 条）：`text`、`time_label`、`is_reply`、`has_quote`、`truncated`、`metrics`（`replies=65, reposts=79, likes=422, views=120K` 这种原样字符串）。
- `source: "api"`（40 条，登出态首屏解析）：`id`、`ts_ms`（精确时间戳）、`text`、`likes`、`retweets`、`handle`、`truncated`。这 40 条全是全文。

## 已知局限

- 样本偏小，且时间窗很窄：截图是 2026-11-17 抓的，时间标签基本是 `2h`／`21h`／`Nov 15` 这种，覆盖不到往前一周。话题也集中在 GLM 5.x、Qwen4、Gemini 反代。换到别的领域，口头禅仍然适用，具体梗不适用。
- 截断条占 31%，NFT_Chen 尤其严重（41 条里只有 14 条全文），它的结尾统计置信度最低。
- 混合声线是统计出来的折中，不等于任何一个人真会这么写。要像某个人，用单一声线开关。
- 截图条的时间标签是相对时间（`2h`、`Nov 15`），只有 40 条 api 来源带精确 `ts_ms`，做时间序列分析不够用。
- 只覆盖推文和评论，不写长推文串（thread）、不写公众号长文。
